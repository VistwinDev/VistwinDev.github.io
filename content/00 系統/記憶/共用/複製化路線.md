# 複製化路線(跨 manager / work / research 的戰略)

## 底層
- 對話/維護/dev-action 的引擎都是 **Claude Code CLI**(`claude -p`,經 bridge)= 完整 dev agent(Bash/Edit/Write/MCP)。
- 能力天花板 = 「那台機器上一個熟練工程師能做的事」(受權限閘 + 模型能力 + 成本限制)。

## 複製論(成立)
- **整套架構與客戶無關**:bridge(跑 CLI)+ n8n(編排)+ vault(markdown-on-git 資料)+ cockpit(模組殼)。
- markdown-on-git = **零鎖定、易 clone**。你賣/部署的是「駕駛艙框架」,客戶自帶 AI 引擎。

## 關鍵糾正(別踩)
- **個人訂閱拿去跑 headless、服務組織自動化 ≈ 違反使用條款**。那是「單機 lab 的 hack」,不是可賣的客戶模型。
- per-客戶產品的 AI 要走 **Claude API(按 token)或 Teams / Enterprise** —— 即「搞定客戶 claude」真正的意思 = **搞定每客戶的 AI 計費 + 身分**。

## 可複製 ≠ 開箱即用
- 每客戶實例化仍要:套 vault schema、做 n8n workflow、建模組、託管、auth。架構複製,**實例化是設定 + 顧問工**。
- 商業形狀:**一半產品(框架 + 模組庫 + 治理)、一半服務(實例化)**。

## 護城河
- 堆疊(CLI + n8n + markdown)別人複製得了。防禦力在 **累積的模組/模板庫 + 整合手藝 + 治理護欄**(propose→approve→apply · 驗證 · rollback)。

## 從 lab → 可賣產品的三段路
1. 個人訂閱 → **API / Teams 計費 + 身分**
2. **託管 + auth / 多人**
3. **modules / templates 變可重用庫** ← cockpit 的「資料驅動模組註冊表」是這段第一步

## 下一步指針
- 正在做:**資料驅動模組註冊表 `/modules`**(見 [[2026-06-30_駕駛艙建置]] 後續)—— 同時是 cockpit 解鎖「加減模組免重編」與「模組庫可複製」的起點。
